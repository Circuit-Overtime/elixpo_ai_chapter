# QFabric v1.0.0 — Stable Research Artifact

QFabric v1.0.0 establishes the first stable compatibility baseline for the
contract-driven Linux–RTOS recovery system and its reproducibility artifact for
the Arduino UNO Q.

## Stable surface

The `qf` command-line interface, QTask ABI version 1, persisted report schemas,
and contract/recovery state semantics are stable as of this release. The
`qf-stage1` command remains available as a compatibility entry point for the
Stage 1 hardware measurement suite. Backward-incompatible changes to these
surfaces require a new major release.

Stable describes the software and artifact interfaces. It does not turn the
project's empirical soft real-time evidence into a hard real-time guarantee or
broaden the experimental claims beyond the documented Arduino UNO Q testbed.

## Research contribution

QFabric detects sustained empirical timing-contract violations, rejects
semantically or temporally inadmissible moves, switches eligible tasks only at
a zero-inflight epoch boundary, and commits or rolls back after post-switch
observation.

## Principal result

In the controlled four-node Linux load-shift replay, ordinary Linux produced a
111.30 ms p95 and 67.3% miss rate against an 80 ms graph deadline. QFabric
recovery reduced p95 to 70.61 ms and misses to 3.7%. A tuned `SCHED_FIFO`
baseline remained stronger at 23.91 ms and zero misses; the manuscript treats
that comparison as a central claim boundary.

## Included evidence

- Direct UNO Q timing, payload, direction, load, concurrency, and LED campaigns.
- Hardware recovery success and rollback scenarios.
- Stage-by-stage specifications, findings, and independent audit reports.
- Stage 11 evaluation across four graph models and seven baselines.
- Source-backed paper graphs, tables, equations, and testbed photograph.
- Python wheel and source distribution for the stable `qf` CLI.

## Installation

```bash
python3 -m pip install qfabric==1.0.0
qf --help
```

Hardware commands require the matching firmware and a full repository checkout.

## Verification

The release process runs the complete hardware-independent unit suite, Ruff,
bytecode compilation, package build, metadata validation, clean-wheel
installation, and a TestPyPI publication/install gate. `SHA256SUMS` covers the
attached paper, distributions, release notes, and final Stage 11 evaluation
report.

The local release bundle can be regenerated after building the Python
distributions and paper:

```bash
python3 scripts/build-release-bundle.py --version 1.0.0
```

## Upgrade from 0.1.0

No CLI, ABI, schema, or recovery-semantics migration is required. Version 1.0.0
promotes the already validated research implementation to its stable public
contract.
