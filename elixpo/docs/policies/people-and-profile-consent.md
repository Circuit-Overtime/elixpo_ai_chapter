# Elixpo people and profile consent policy

**Status:** Active operating policy  
**Effective:** 2026-10-17  
**Machine-readable source:** [`content/people.json`](../../content/people.json)

Elixpo records attributable public work without turning contribution history
into invented employment, membership, or endorsement claims. This policy
defines what may be published from public evidence and what requires a person's
explicit opt-in.

## Public-evidence basis

Elixpo may conservatively publish a person's public name, GitHub handle, public
GitHub profile image, linked public portfolio, and attributable work when the
source is cited. A commit, issue, pull request, paper, or repository role proves
only what that record actually shows. It does not by itself establish
employment, organization leadership, formal review, or a private relationship.

## Explicit consent basis

Recorded opt-in consent is required before publishing:

- a custom biography not supported by cited public material;
- non-public role dates, reasons for departure, or internal responsibilities;
- private contact information or personal details;
- supplied photography that is not already used as a public profile image; or
- a testimonial, endorsement, or affiliation claim extending beyond the public
  evidence.

Consent records are administrative evidence and are not published merely to
prove consent. Public registry entries state `profileSource: consented` when
consent, rather than public evidence alone, is the publication basis.

## Current publication resolution

The current people and contributor edition does not publish any consent-gated
material. Every listed profile uses `profileSource: public-evidence-only`, a
public GitHub identity or profile image, and linked public work. Custom
biographies, supplied photography, private contact information, non-public role
dates, departure explanations, testimonials, and private affiliation details
are withheld. They may be added only after an administrative opt-in record is
created and the public registry changes to `profileSource: consented`.

This is a deliberate resolution, not implied consent. Elixpo does not need to
solicit personal material merely to make the directory appear complete.

## Corrections, disputes, and removal

A person may request correction or removal through the issue route recorded in
`content/people.json`. Optional disputed profile material is hidden while the
request is reviewed. Removal from an Elixpo profile does not rewrite independent
public Git history, paper authorship, or upstream records controlled elsewhere.

Profiles must link their evidence, avoid sensitive inferences, and use the
narrowest accurate role. Photos, biographies, alumni entries, and advisory roles
are never added merely to make a page appear more complete.
